## 1. Процесс хартиясы

Мақсат — GadgetStore үшін жұмыс ағынын «басталған жұмыс санымен» емес, Done-ға жеткізілген item және cycle time арқылы басқару. Әр item солдан оңға: Ready → Doing → Review → Done өтеді. Done-нан қайта ашылған жұмыс жеке жаңа оқиға ретінде жазылады.

| Элемент | Sprint 1 | Sprint 2 | Ереже |
| --- | --- | --- | --- |
| Бағандар | Ready, Doing, Review, Done | Ready, Doing, Review, Done | Pull жүйесі: жұмыс тек бос орын бар келесі бағанға өтеді. |
| Doing WIP | 2 | 2 | Doing толық болса, жаңа item басталмайды. |
| Review WIP | 1 | 2 | Retro-дан кейін екі тексеру item-і қатар өте алады. |
| Definition of Ready | Тақырып және қысқа нәтиже | Мақсат, acceptance, тәуелділік, өлшем | Төрт белгі жоқ item Doing-ке тартылмайды. |
| Definition of Done | Код/құжат бар | Код/құжат + acceptance + test/дәлел | Review аяқталып, дәлел тіркелгенде ғана Done. |
| Cadence | Күнделікті қысқа шолу | Күнделікті шолу + апталық review/retro | Күй ауысуының күні журналға түседі. |

### Спринт мақсаттары

Sprint 1: каталог пен тапсырыс сценарийінің негізгі тексерулерін аяқтау. Sprint 2: WIP тәртібін орнықтырып, Review кезегін шектеу арқылы cycle time-ды азайту. Expedite тек blocker үшін, бірден бір item-тен көп емес және WIP-тен тыс емес.

## 2. Sprint 1: жоспар, тақта және шолу

Sprint 1-де 13–19 қазан аралығында төрт item аяқталды. Жоспарланған нәтижелер: каталог деректерін тексеру, серверлік тапсырыс валидациясы, API регрессия тесті және іске қосу нұсқаулығы. Тақтадағы acceptance белгілері — оқу симуляциясындағы қабылдау дәлелдері.

| ID | Тарихша | Doing | Review | Done | Cycle |
| --- | --- | --- | --- | --- | --- |
| GS-01 | Каталог деректерін тексеру | 13-Oct | 14-Oct | 14-Oct | 1 күн |
| GS-02 | Тапсырыс серверлік тексеру | 14-Oct | 16-Oct | 17-Oct | 3 күн |
| GS-03 | API регрессия тесті | 15-Oct | 17-Oct | 18-Oct | 3 күн |
| GS-04 | Іске қосу нұсқаулығы | 14-Oct | 18-Oct | 19-Oct | 5 күн |

### Sprint 1 review

4 item Done-ға өтті. CFD-де 15-Oct күні Doing бағанында 3 item болды, ал лимит — 2. Бұл Doing WIP бұзылысы және негізгі тар жер: Review босамай тұрып жаңа item басталған. GS-04 құжат item-і 5 күн жүргендіктен, шағын іріктемеде P85 үшін консервативті баға ретінде ең ұзақ cycle time, яғни 5 күн алынды.

### Ретроспектива

| Бақылау | Түбір себеп | Sprint 2 әрекеті | Бақылау өлшемі |
| --- | --- | --- | --- |
| Doing WIP: 3 / 2 | Review босамай тұрып жаңа item басталды | Pull алдында Doing санын тексеру | Күнделікті CFD; 0 бұзылыс |
| Орташа cycle: 3.0 күн | Құжат пен тест бір кезекте жиналды | DoR-ге acceptance және өлшем қосу | Cycle time |
| Review кезегі айқын емес | Тексеру иесі/дәлелі жазылмады | Review WIP=2; DoD-де дәлел сілтемесі | Review age |

Нақты таңдалған бір әрекет: Doing WIP=2 тәртібі. Орындау механизмі: күнделікті шолуда Doing саны тексеріледі; лимит толса, жаңа item басталмайды. Sprint 2 нәтижесі: 0 бұзылыс.

## 3. Flow-метрикалар және CFD

Excel файлындағы «Тақта» парағы — бастапқы дерек көзі. Cycle time = Done күні − Doing күні. Throughput = сол спринтте Done болған item саны. CFD үшін әр күндегі Ready, Doing, Review және Done саны әр item-нің күй ауысу күндері арқылы есептеледі. Сондықтан сандар қолмен толтырылған қорытынды емес.

| Метрика | Sprint 1 | Sprint 2 | Қалай есептелді |
| --- | --- | --- | --- |
| Throughput | 4 | 5 | Тақтадағы спринт бойынша Done item саны |
| Орташа cycle time | 3.0 күн | 1.8 күн | Each item үшін Done − Doing, содан соң AVERAGE |
| P85 cycle time | 5 күн | 2 күн | n=4/5 шағын болғандықтан консервативті MAX |
| Doing WIP бұзылуы | 1 күн | 0 күн | CFD күндерінде Doing > 2 болатын күндер |

### CFD-ді оқу

Sprint 1-де 15-Oct күні Doing=3 болды — WIP шегі бұзылған жалғыз күн. 16–18 Oct аралығында Review-де item қалып, GS-04 ұзақ cycle тудырды. Sprint 2-де Ready көлемі біртіндеп Doing-ке тартылды, Doing ешқашан 2-ден аспады, ал Review ең көбі 2 болды. Бұл тар жердің бақылауға алынғанын көрсетеді, бірақ симуляция болғандықтан тек келесі нақты спринтте осы ережелерді өлшеумен растау қажет.

## 4. Sprint 2: әрекетті орындау және салыстыру

Sprint 2-де 20–25 қазан аралығында бес item аяқталды: профиль деректерін азайту, тапсырыс API лимиті, backup restore тексеруі, құжатты жаңарту және бюджет драйверлерін есептеу. GS-05–GS-07 үшін acceptance жолында «симуляция» белгісі ашық көрсетілген.

| Өзгеріс | Неліктен | Нәтиже |
| --- | --- | --- |

Себеп-салдар қорытындысы: Sprint 2-дегі нәтиже WIP-ті шектеу, pull тәртібі және нақты Ready/Done шарттарымен байланысты. Бұл бір ғана симуляция, сондықтан өнімділіктің артуын тұрақты үрдіс деп айтуға әлі ерте; келесі спринттерде дәл сол журнал мен метрикалар сақталуы керек.

## 5. Қорытынды және тапсыру құрамы

Екі спринттік симуляция GadgetStore жұмысын циклмен басқару үлгісін берді: Sprint 1-де Doing WIP лимиті бұзылып, 5 күндік ұзақ item пайда болды. Ретроспективадан кейінгі нақты әрекет — Doing WIP=2 тәртібі — Sprint 2-де 0 бұзылыспен орындалды. Журналдан есептелген көрсеткіштер throughput-тың 4-тен 5-ке өскенін, орташа cycle time-ның 3.0-ден 1.8 күнге азайғанын көрсетті.
